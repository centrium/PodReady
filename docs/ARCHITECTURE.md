# PodReady Architecture

## Workspace Structure
PodReady uses a Turborepo + pnpm workspace structure:
- `apps/desktop`: The main Tauri + React + Vite application.
  - `src/`: React frontend UI.
  - `src-tauri/`: Rust backend, media engine, binary resolver, and Whisper transcription runtime.
- `packages/domain`: Shared TypeScript interfaces between the frontend and backend.
- `packages/ui`: Shared Tailwind configuration and future shared UI components.

## Boundaries
### React ↔ Tauri ↔ Rust
The React UI communicates exclusively via Tauri IPC commands. It does not invoke media tools or AI runtimes directly. The UI requests operations from Rust, and Rust responds with strongly-typed domain models.

### Bundled Media Runtime & Self-Containment
PodReady owns and bundles all media execution tools and speech models:
```text
Bundled Media Runtime
├── FFmpeg (audio analysis, filter graphs, two-pass loudnorm, MP3 encoding)
├── FFprobe (container & stream inspection)
├── Whisper (native whisper.cpp speech-to-text inference with Metal acceleration)
└── Whisper Speech Model (pinned ggml-large-v3-turbo model with SHA-256 integrity check)
```

Binary and resource resolution is centralized strictly in `apps/desktop/src-tauri/src/media/binaries.rs`:
1. Production macOS App bundle: resolves from `Contents/Resources/resources/bin` and `models/`.
2. Development workspace: resolves from `apps/desktop/src-tauri/resources/`.
3. Hermetic testing: supports `PODREADY_RESOURCES_DIR` environment override.
4. **Zero Production PATH Dependency**: PodReady does NOT fall back to system PATH (e.g. `/opt/homebrew`, `/usr/local/bin`) in production.

### Media Inspection Boundary
Rust invokes bundled `ffprobe` inside `apps/desktop/src-tauri/src/media/ffprobe.rs`. It parses the raw JSON output from `ffprobe` into strongly typed `AudioMeasurements` and `MediaFormat` structs.

### Audio Analysis & Assessment Separation
Objective measurement (`media/analysis.rs`) is completely decoupled from business assessment (`assessment/engine.rs`):
```text
Source Audio / Candidate Audio
      ↓
Objective Measurement (ebur128, silencedetect, astats via bundled FFmpeg)
      ↓
PodcastProfile (Stereo -16 LUFS / Mono -19 LUFS)
      ↓
Assessment (Ready, Attention, Needs Attention)
```

### Processing Engine & Verification Loop
The processing layer (`media/processing.rs`) executes approved `FixActions` generated by the `FixPlan` engine:
```text
FixPlan
   ↓
Processing Engine (two-pass FFmpeg loudnorm)
   ↓
Candidate output file
   ↓
Re-measurement (analysis.rs)
   ↓
Verification Assessment (assessment/engine.rs)
```

### Publishing Package & Local Speech-to-Text Transcription
The publishing package pipeline (`export/package.rs`) coordinates final export:
```text
Processed / Verified Candidate
        ↓
Publishing MP3 Encoding (192kbps stereo / 128kbps mono + ID3v2 tags & artwork)
        ↓
Final MP3 Verification (independent re-measurement & assessment)
        ↓
Local Whisper Transcription (transcription/engine.rs)
        ↓
Assemble PodReady Package ([Stem]_PodReady/)
├── [Stem]_ready.mp3
├── [Stem]_transcript.txt
└── [Stem]_report.json
```

**Resilience Guarantee**: Audio readiness is sovereign. If transcription fails, the verified MP3 and report are preserved and delivered without data loss.

### File Handling & Immutability Guarantee
The original source files are strictly read-only and are never modified or overwritten.
